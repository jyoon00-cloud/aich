# 선수 능력치 교정 지시 (Sonnet 워커용, Opus 설계)

목표: 연도별 능력치를 **기억이 아니라 수집된 근거로** 다시 매긴다.

## 먼저 읽기
- `/home/user/aich/rules/db/README.md`: 열 정의와 수치 기준표. 기준표는 바꾸지 않는다.
- `_work/brief_stats.md`의 "보정 기준" 절: 분포 목표.

## 입력 (배정 파일마다)
- 현재 값: `rules/db/{연도}/{리그}.csv` (`id,team,pos,lan,phy,skr,tf,vis,style`). 이전 세션에서 기억으로 쓴 값이라 검증되지 않았다. **행 구성·id·team·pos·행 순서는 바꾸지 않는다.**
- 근거: `_work/redo/ev/{연도}_{리그}.md`
  - 머리말 `순위:` 그 스플릿 팀 순위(파일마다 정규시즌/플레이오프 기준이 다르니 머리말 확인).
  - `## {id}` 아래
    - `스플릿:` 그 스플릿 개인 성적(G, W, KDA, KP, DMG/M, CS/M)
    - `직전 해:` 직전 해 수상·소속(수상 칸에 다른 해 수상이 섞여 있으면 **직전 해 것만** 쓴다)
    - `직전 해 대회(YYYY):` 직전 해 출전 대회와 순위(월즈·MSI·리그 플레이오프 등)
  - `[주전]` 표시가 주전이다.
- 2013~2014는 직전 해 정보가 빈약하다. 스플릿 성적과 팀 순위 비중을 높인다.

## 산정 방법
1. **팀 위치 → OVR 기본 구간** (README 기준표)
   - 순위 상위 2팀 주전은 상위권, 중간은 중위권, 하위 2~3팀은 하위권.
   - LEC −10, LCS −20.
2. **직전 해 실적 → 가산**
   - 월즈 4강 이상 또는 MSI 우승·준우승 팀 주전, 또는 직전 해 리그 MVP·퍼스트 올프로: 국제대회 최상위 구간(465~485)까지 올릴 수 있다.
   - 월즈 8강, 세컨드·서드 올프로: +5~10.
   - 근거 줄에 없는 실적은 반영하지 않는다.
3. **개인 성적 → 같은 파일 같은 포지션 주전끼리 비교해 ±10 조정**
   - 근거: KDA, KP, DMG/M, CS/M. 출전 수(G)가 적으면 성적 비중을 낮춘다.
4. **5개 능력치 분배 (±30 안에서 개성)**
   - lan: 같은 포지션 대비 CS/M (정글·서폿은 KDA 비중)
   - phy: DMG/M와 KDA
   - skr: KP와 KDA
   - tf: KP와 팀 성적
   - vis: 서폿·정글이 높은 편이고 KP로 보정
   - 해시·난수 지터로 일괄 생성하지 않는다.
5. **style**
   - 위 수치 프로필에 맞춘다: 높은 DMG/M는 캐리형, 높은 KP의 정글·서폿은 이니시형·교전형, 높은 CS/M에 낮은 KP는 성장형·라인전형 등.
   - 현재 값이 근거와 맞으면 유지하고, 맞지 않으면 바꾼다.
6. **비주전·근거 없는 선수**
   - 같은 팀 같은 포지션 주전보다 낮게 둔다(410 안팎).
   - 근거 파일에 없거나 스플릿 성적이 `못 찾음`인 **주전**은 Bash curl로 Leaguepedia를 직접 조회해 확인한다:
     - 그 이벤트 Player_Statistics 페이지(`_work/redo/events.txt`의 이벤트 이름 + `/Player_Statistics`)
     - 또는 선수 페이지 `https://lol.fandom.com/api.php?action=parse&format=json&prop=text&page=<leaguepedia_page>`
   - 그래도 없으면 WebSearch/WebFetch로 확인하고 URL을 남긴다. **기억으로 채우지 않는다.**
7. **분포 확인 (파일마다, LCK·LPL 기준)**
   - 주전 OVR 중앙값 430~435
   - 그해 리그 최고 선수 465~480. 485 이상은 역대급 전성기만.
   - 하위권 주전 405~425
   - 능력치 상한 490 (Faker 500, Uzi·Caps 495)
8. **연속성**
   - 배정 연도를 오름차순으로 처리한다.
   - 같은 선수의 앞 연도(이미 교정한 파일)와 흐름이 자연스러운지 본다(성장 → 전성기 → 하락).
   - 단, 근거가 우선이다. 나중 해의 활약을 앞 연도로 당겨오지 않는다.

## 출력
- `rules/db/{연도}/{리그}.csv` 덮어쓰기. 같은 헤더·같은 행 수·같은 순서. UTF-8, 따옴표 없음, 정수.
- 변경 로그 `_work/redo/changes/{연도}_{리그}.md`: 선수마다 한 줄.
  `id: OVR 이전→이후 (lan/phy/skr/tf/vis 이후값, style) — 근거: 팀 N위, KDA x, 직전 해 … — 출처 URL`
  - 출처 URL은 ev 파일에 적힌 것 또는 직접 조회한 것만 쓴다.
- 파일마다 작성 후 다시 읽어 행 수가 같은지 확인한다.
- git 명령은 하지 않는다.
- 끝나면 짧게 보고: 파일별 행 수, 주전 OVR 중앙값·최고값, 직접 조회한 선수, 불확실한 점.
