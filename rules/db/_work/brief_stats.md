# 작업 지시: 연도별 능력치 입력

먼저 읽기: `/mnt/project-files/rules/db/README.md` (수치 기준표, 열 정의), 기준 샘플 `/mnt/project-files/rules/db/_work/old/2024_LCK.csv` (T1 5명).

## 입력 자료 (Leaguepedia에서 수집 완료, 그대로 믿어도 됨)
- `_work/skel/{연도}_{리그}.csv`: 그해 스프링(첫 스플릿) 개막 로스터. 열 `id,team,pos,...,games`. games = 그 스플릿 출전 세트 수(비어 있으면 미상). **행 구성과 id는 바꾸지 않는다.**
- `_work/standings.txt`: 그 스플릿 정규시즌 순위(약칭). 리그 내 위치 판단에 쓴다.
- `_work/players_master.csv`: 선수별 이름·출생연도·국적·커리어 시즌 목록.
- `_work/old/{연도}_{리그}.csv`: 이전에 기억으로 쓴 값(있으면). 참고만. 검증된 값 아님.

## 할 일
배정받은 각 파일마다 `/mnt/project-files/rules/db/{연도}/{리그}.csv`를 **새로 덮어쓴다**:
`id,team,pos,lan,phy,skr,tf,vis,style` (games 열은 빼고, 행 순서 유지)
- team: 그해 정식 팀명으로 정리 (예: `skt 2` → `SK Telecom T1 2`, `clg` → `Counter Logic Gaming`). 같은 팀은 파일 안에서 같은 표기.
- 능력치: README 기준표의 OVR 구간 + 리그 보정(LEC −10, LCS −20). **그해 그 리그 안의 상대적 위치**와 순위, 선수 특징(라인전형, 한타형, 시야형 서폿 등)을 반영. 5개는 ±30 내외로 개성.
- 그해 개막 시점 기준이다. 나중 해의 활약을 당겨오지 않는다(예: 2020년 신인을 2023년 전성기 수치로 쓰지 않음). 신인·첫 시즌 선수는 400~425 근처.
- 출전 적은 교체 선수(games가 팀 주전보다 훨씬 적음)는 보통 주전보다 낮게.
- 같은 선수가 맡은 다른 연도 파일과 흐름이 자연스럽게(성장 → 전성기 → 하락).
- 각 능력치 상한 490 (Faker 500, Uzi·Caps 495). 하한은 대략 370.
- style: 한국어 한 단어 (캐리형, 운영형, 교전형, 안정형, 이니시형, 로밍형, 성장형, 보호형, 라인전형, 한타형 등).
- 모르는 선수는 웹 검색(lol.fandom.com 페이지 이름이 players_master의 leaguepedia_page)으로 간단히 확인. 아는 선수는 검색하지 않는다. Liquipedia는 차단되어 있으니 쓰지 않는다. 검색은 꼭 필요한 만큼만.

## 파일 규칙
- `/mnt/project-files`는 네트워크 마운트: 경로 끝 슬래시, 폴더 전체 검색 금지, 배정받은 파일만 쓴다.
- UTF-8, 헤더 포함, 따옴표 없이. 숫자는 정수.
- 파일마다 작성 후 약 10초 뒤 다시 읽어 행 수가 skel과 같은지 확인.
- 끝나면 파일별 행 수와 불확실했던 점을 5줄 이내로 보고.

## 보정 기준 (LCK 결과 검수 후 추가)
지나치게 몰리지 않게 분포를 넓힌다. LCK·LPL 기준 한 파일 안에서:
- 우승권 팀 주전 핵심: OVR 455~475, 그해 리그 최고 선수 465~480(역대급 전성기만 485 이상).
- 주전 전체 중앙값 약 430~435. 하위권 팀 주전 405~425. 출전 적은 교체 410 안팎.
- LEC는 위 값에서 −10, LCS는 −20.
- 5개 능력치는 선수 특징에 맞게 직접 정한다(해시·난수 지터로 일괄 생성하지 않는다). 예: 라인전 강한 탑은 lan·phy 높고 vis 낮게, 시야형 서폿은 vis 높게.
